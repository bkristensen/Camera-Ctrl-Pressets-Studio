## Search before reporting

**Report a bug or suggest a feature**\
<https://github.com/bkristensen/Camera-Ctrl-Pressets-Studio/issues?q=is%3Aissue>\
![QR code for the project’s GitHub issues](../images/qr/issues.png)

1. Open the project's [Issues tab](https://github.com/bkristensen/Camera-Ctrl-Pressets-Studio/issues?q=is%3Aissue). Search for key terms from the symptom or request, such as `is:issue Brio zoom` or `is:issue label:enhancement preset`.
2. Check open and closed results. Read similar reports for matching symptoms and workarounds.
3. On a matching issue, select **Subscribe** in the sidebar to receive updates, or react with 👍 to show that it affects you. Add a comment if you can contribute details such as a different camera, a test result or a reliable reproduction.

![Issue search above the Open and Closed tabs. New issue is at upper right.](../images/reporting/github-issues.png)

## Open a report

In the app, open **Contact & About → Contact**. Choose **Report an issue** for a bug or **Request a new feature** for a suggestion. If a newer release is available, open it and check whether it solves the problem. Choose **No** if you want to continue to the GitHub draft.

Use English where possible so more people can find and follow the report. Write one issue per problem or request. Use a title that names the symptom or desired behaviour.

For a bug, include the Camera Control Studio version, Windows version, camera model, relevant camera or capture software, and the order in which you started the apps. Describe the exact steps, what you expected, what happened and how often. For a request, describe the task you want to accomplish and how you would use the feature.

![GitHub issue editor with title, description, file upload and Create button](../images/reporting/github-new-issue.png)

If **Type** is available, use **Bug** for unexpected behaviour, **Feature** for a request, or **Task** for a defined piece of work. If you can apply labels, use the most relevant ones, such as `bug`, `enhancement`, `documentation` or `accessibility`. Maintainers can add metadata after submission.

![GitHub label picker](../images/reporting/github-issue-labels.png)

![Example labels and their meanings](../images/reporting/github-label-reference.png)

## Attach evidence

When you report a bug, the app offers to save a support ZIP. You can also choose **Save support ZIP** in **Contact**. The package contains a screenshot of the app, saved profiles, the window layout, and available logs.

Review the package before sharing. Remove private information such as file paths, meeting details and IDs. Drag the ZIP or the relevant files into the GitHub draft. Check the issue in **Preview**, then choose **Create**.

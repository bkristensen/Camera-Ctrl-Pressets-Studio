# कोड हस्ताक्षर नीति

SignPath फाउंडेशन पात्र ओपन-सोर्स परियोजनाओं के लिए निःशुल्क हस्ताक्षर की पेशकश करता है। स्वीकृति आवश्यक है. प्रमाणपत्र प्रकाशक के रूप में SignPath फाउंडेशन की पहचान करता है; सत्यापित बिल्ड को सेवा लिंक स्रोत रिपॉजिटरी से जोड़ता है। परियोजना ने SignPath फाउंडेशन पर हस्ताक्षर के लिए आवेदन किया है। आवेदन लंबित है, और GitHub डाउनलोड अहस्ताक्षरित हैं।

आवेदन करने से पहले, इसके लाइसेंस के तहत स्रोत प्रकाशित करें। प्रोजेक्ट को चालू रखें. एक रिलीज़ प्रकाशित करें, ऐप का दस्तावेज़ीकरण करें और बिल्ड को सत्यापन योग्य बनाएं। केवल अपनी परियोजना फ़ाइलों पर ही हस्ताक्षर करें। रिपॉजिटरी से क्रेडेंशियल्स पर हस्ताक्षर करते रहें।

[ गोपनीयता नीति](../../PRIVACY.md) ऐप, इसके GitHub अपडेट चेक और गाइडव्यूअर के WebView2 रनटाइम को कवर करती है।

## जबकि आवेदन लंबित है

- जांचें कि सार्वजनिक रिपॉजिटरी में **Actions** के तहत एक सफल विंडोज बिल्ड है। उस वर्कफ़्लो को SignPath एकीकरण के आधार के रूप में उपयोग करें।
- प्रतिबद्धताओं, समीक्षाओं और अनुमोदनों पर हस्ताक्षर करने के लिए जिम्मेदार लोगों की पुष्टि करें। GitHub और SignPath पर टीम के सभी सदस्यों के लिए बहु-कारक प्रमाणीकरण चालू करें।
- यह पुष्टि करने के लिए SignPath से पूछें कि WebView2 SDK बायनेरिज़ और Inno Setup इंस्टॉलर को कैसे संभाला जाना चाहिए। पैकेज में माइक्रोसॉफ्ट के एसडीके बायनेरिज़ और लोडर शामिल हैं। ऐप उपयोगकर्ता के पीसी पर इंस्टॉल किए गए WebView2 रनटाइम का उपयोग करता है। एप्लिकेशन में इन निर्भरताओं को सूचीबद्ध करें और उनकी सूचनाओं को सुरक्षित रखें।
- एक जोड़ें **कोड हस्ताक्षर नीति** से लिंक करें GitHub एप्लिकेशन में दिए गए डाउनलोड पेज के लिए नोट्स जारी करें। उन डाउनलोडों की वास्तविक हस्ताक्षर स्थिति बताएं।

## SignPath के प्रोजेक्ट स्वीकार करने के बाद

- इस पृष्ठ पर स्वीकृत SignPath एट्रिब्यूशन और प्रतिबद्धताओं, समीक्षकों और अनुमोदकों के लिए पुष्टि किए गए नाम या अनुमति समूह जोड़ें।
- विश्वसनीय GitHub Actions बिल्ड से कलाकृतियों को स्वीकार करने के लिए SignPath को कॉन्फ़िगर करें। प्रोजेक्ट बायनेरिज़ पर हस्ताक्षर करना प्रतिबंधित करें। एक साथ सबमिट की गई फ़ाइलों में उत्पाद का नाम और मेल खाने वाले उत्पाद संस्करण को सेट और लागू करें।
- ZIP के लिए, पैकेजिंग से पहले निष्पादन योग्य ऐप पर हस्ताक्षर करें। इंस्टॉलर के लिए, पूर्ण इंस्टॉलर पर हस्ताक्षर करने से पहले हस्ताक्षरित ऐप को इंस्टॉलर में डालें। प्रत्येक रिलीज़ हस्ताक्षर अनुरोध के लिए मैन्युअल अनुमोदन प्राप्त करें।
- ऑथेंटिकोड हस्ताक्षर और टाइमस्टैम्प सत्यापित करें, फिर SHA-256 चेकसम जेनरेट करें। रिलीज़ नोट्स में एक **Code हस्ताक्षर नीति** लिंक और हस्ताक्षर स्थिति शामिल करें। प्रकाशन से पहले अपलोड की गई फ़ाइलों और हैश को सत्यापित करें।

सीधे GitHub डाउनलोड के लिए, एक वैध हस्ताक्षर प्रकाशक की पहचान करता है और बाइनरी की अखंडता की रक्षा करता है। प्रतिष्ठा निर्माण के दौरान एक नया डाउनलोड अभी भी स्मार्टस्क्रीन को ट्रिगर कर सकता है। स्टोर के माध्यम से पहली बार वितरण के लिए, Microsoft ने MSIX पैकेज स्वीकार किए जाने पर हस्ताक्षर किए हैं।

वर्तमान उपयोगकर्ता के विंडोज़ प्रमाणपत्र स्टोर के माध्यम से उपलब्ध सार्वजनिक रूप से विश्वसनीय कोड-हस्ताक्षर प्रमाणपत्र के लिए, पोर्टेबल ZIP के लिए `scripts/build.ps1 -CertificateThumbprint <thumbprint> -SignToolPath <path>` का उपयोग करें। ऐप निष्पादन योग्य और जेनरेट किए गए इंस्टॉलर दोनों पर हस्ताक्षर करने के लिए `scripts/build-installer.ps1` के साथ समान पैरामीटर का उपयोग करें। SignPath अनुमोदन के लिए अपने स्वयं के हस्ताक्षरित वर्कफ़्लो की आवश्यकता होती है।

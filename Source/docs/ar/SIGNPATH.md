# سياسة توقيع الكود

تقدم مؤسسة SignPath توقيعًا مجانيًا للمشاريع المؤهلة مفتوحة المصدر. القبول مطلوب. تحدد الشهادة مؤسسة SignPath كناشر؛ يتم إنشاء روابط الخدمة التي تم التحقق منها في المستودع المصدر. تقدم المشروع بطلب لتوقيع مؤسسة SignPath. التطبيق معلق، وتنزيلات GitHub تظل غير موقعة.

قبل التقديم، قم بنشر المصدر بموجب ترخيصه. إبقاء المشروع الحالي. قم بنشر إصدار وتوثيق التطبيق وجعل البناء قابلاً للتحقق. قم بالتوقيع على ملفات المشروع الخاصة بك فقط. استمر في توقيع بيانات الاعتماد خارج المستودع.

تغطي سياسة الخصوصية [](../../PRIVACY.md) التطبيق وفحص تحديث GitHub ووقت تشغيل WebView2 الخاص بـ GuideViewer.

## بينما التطبيق معلق

- تأكد من أن المستودع العام يحتوي على إصدار Windows ناجح ضمن **Actions**. استخدم سير العمل هذا كأساس لتكامل SignPath.
- تأكد من الأشخاص المسؤولين عن الالتزامات والمراجعات وتوقيع الموافقات. قم بتشغيل المصادقة متعددة العوامل لجميع أعضاء الفريق على GitHub وSignPath.
- اطلب من SignPath تأكيد كيفية التعامل مع ثنائيات WebView2 SDK ومثبت Inno Setup. تتضمن الحزم ثنائيات وأدوات تحميل SDK من Microsoft. يستخدم التطبيق WebView2 Runtime المثبت على جهاز الكمبيوتر الخاص بالمستخدم. قم بإدراج هذه التبعيات في التطبيق واحتفظ بإشعاراتها.
- أضف رابط سياسة توقيع **Code ** إلى ملاحظات إصدار GitHub لصفحة التنزيل المتوفرة في التطبيق. اذكر حالة التوقيع الفعلية لتلك التنزيلات.

## بعد أن يقبل SignPath المشروع

- أضف إسناد SignPath المعتمد والأسماء المؤكدة أو مجموعات الأذونات للملتزمين والمراجعين والموافقين إلى هذه الصفحة.
- قم بتكوين SignPath لقبول العناصر من إصدار GitHub Actions الموثوق به. تقييد التوقيع على ثنائيات المشروع. قم بتعيين وتنفيذ اسم المنتج وإصدار المنتج المطابق عبر الملفات المرسلة معًا.
- بالنسبة إلى ZIP، قم بالتوقيع على التطبيق القابل للتنفيذ قبل التعبئة. بالنسبة إلى أداة التثبيت، ضع التطبيق الموقع القابل للتنفيذ في أداة التثبيت قبل التوقيع على أداة التثبيت النهائية. الحصول على موافقة يدوية لكل طلب توقيع إصدار.
- تحقق من توقيعات رمز المصادقة والطوابع الزمنية، ثم قم بإنشاء المجموع الاختباري SHA-256. قم بتضمين رابط سياسة توقيع **Code ورابط ** وحالة التوقيع في ملاحظات الإصدار. تحقق من الملفات والتجزئة التي تم تحميلها قبل النشر.

بالنسبة للتنزيلات المباشرة لـ GitHub، يحدد التوقيع الصالح الناشر ويحمي سلامة الملف الثنائي. لا يزال بإمكان التنزيل الجديد تشغيل SmartScreen أثناء بناء السمعة. بالنسبة للتوزيع الذي يتم تشغيله لأول مرة من خلال المتجر، توقع Microsoft قبول حزم MSIX.

للحصول على شهادة توقيع التعليمات البرمجية الموثوق بها بشكل عام والمتوفرة من خلال مخزن شهادات Windows الخاص بالمستخدم الحالي، استخدم `scripts/build.ps1 -CertificateThumbprint <thumbprint> -SignToolPath <path>` لجهاز ZIP المحمول. استخدم نفس المعلمات مع `scripts/build-installer.ps1` لتوقيع كل من التطبيق القابل للتنفيذ والمثبت الذي تم إنشاؤه. تتطلب الموافقة على SignPath سير عمل التوقيع الخاص بها.
